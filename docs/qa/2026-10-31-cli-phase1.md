# 第一期 CLI 验证记录（2026-10-31）

这是发布前记录，不是 `v0.4.0` 已发布或已完成整体验收的声明。任务与最终检查见[集成 PR #94](https://github.com/witkitlab/witshield/pull/94)；按系统执行的步骤见[CLI 演练清单](../testing-check-cli.md)。

## 已完成的软件检查

- 功能集成树 `02010cda5458d9f85782e3ccc7973fcc40f4a8d0` 的 [GitHub CI](https://github.com/witkitlab/witshield/actions/runs/41202547361) 和 [CodeQL](https://github.com/witkitlab/witshield/actions/runs/41202547323) 均通过；后续文案与记录改动仍以集成 PR 的最终检查为准。
- 本地完整 Go race 测试、vet、gofmt、staticcheck、gosec 通过。使用 Go 1.27.3，govulncheck 未发现可达漏洞；另有 3 项所需模块漏洞未被代码调用。gosec 没有新增抑制项。
- 前端 lint、类型检查、41 项测试及 Pages、嵌入式构建通过。npm audit 没有 critical/high，仍有 21 项 moderate 开发工具依赖告警，不代表依赖完全没有风险。
- 下载和镜像夹具覆盖哈希不符、签名失败、参数透传、清理、版本解析和归档布局。夹具中的签名验证器是模拟原语；它不能证明真实发布的 Sigstore 签名已经通过。
- 中英文官网完成浏览器响应式、复制按钮及回退验证。两份最新真实虚拟机演示 GIF 字节一致，1440×900，25.5 秒，361,985 字节，SHA-256 为 `791d6020de7d1ca93fd28a5c9bd1843bebc64d1d144c4995af961a5081d8bd66`；[素材说明](../demo/README.md)明确区分真实输出重播与实时录屏。最终 Pages 构建通过，320 和 1440 像素真实浏览器检查均返回 GIF HTTP 200、解码尺寸正确、响应体 SHA-256 与源码一致，无横向溢出和运行时错误。

本环境默认 umask 为 `0077`，会使原有“权限过宽”负例文件变成 `0600`。完整 Go 测试显式使用 `umask 022`，保留原来的安全断言，没有放宽测试条件。

## 隔离容器演练

Ubuntu 24.04 amd64 容器使用真实 sshd、新 TCP 连接及仅用于测试的 systemctl/SIGHUP 适配器，完成确认、超时、Ctrl-C、kill -9 后启动恢复、无公钥拒绝和 shadow 权限修复。修改后新密钥连接可用，密码认证被拒绝；恢复后核对配置及新连接。

这组结果不属于真实 systemd 虚拟机矩阵。演示素材来源提交为 `c661430`；后续受限文件读取修改另外重跑了 UID 0 CLI 测试和受影响 SSH 场景。临时容器及其测试密钥已销毁，公开素材没有凭据、密钥正文或真实服务器日志。

## 真实虚拟机矩阵

Debian 使用程序内嵌 VCS 提交 `dfa093f35f7d569071ef83fa58907c3b0597e956`（`vcs.modified=false`），程序 SHA-256 为 `c6175de872ee349ac970d95e0e5ea0d4a6adf602ca4d222ffca5cca33757ff55`；CLI 受限读取修正源自 `be7c87e`，后续两句显示文案的修改另有 CLI race 测试。首轮虚拟机密码探针的辅助脚本位于 noexec 临时文件系统，未能提交密码，相关判断已作废；上述 PASS 来自修正夹具、证明密码基线成功后的完整重跑。

Ubuntu 24.04 的无公钥场景曾因外部探针 8 秒总预算耗尽标为 `BLOCKED`，原记录保留；同一虚拟机以 20 秒有界预算复核，证明拒绝修复、配置摘要不变和真实 password 认证可用，再完成 shadow 检查。没有修改产品超时、认证保护或已通过路径的断言。

ARM64 初次 SCP 在产品运行前返回错误，初次 stderr 未保留，原因不能确定；记录独立保留。一次受控复核传输成功，安装后核对程序 SHA-256、属主和权限，再执行全部产品场景。ARM64 测试程序内嵌 VCS 为 `4f8b998459dd6dd2d6a270b35e8add7e94d22ec4`，`vcs.modified=false`，SHA-256 为 `8a8bc171c004e57ec5b775a2e72467451ac84c18a7cd15e4bf49aff0b7ced0d2`。

四台的 32 项扫描/SSH/权限场景和 8 项真实 APT 场景均通过。脱敏后的[机器可读记录](2026-10-31-cli-vm-results.json)包含官方镜像校验和、实际程序构建信息、内存、场景结果和包变更摘要；未包含凭据、密钥、SSH 指纹、完整系统配置或串口日志。

完成证据核对后，承载虚拟机的专用非 privileged 容器及其 `/vms` tmpfs 已销毁，客体磁盘、seed 和临时测试凭据未保留在公开源码或宿主挂载目录中。

这组结果覆盖真实客体内核、systemd 和 SSH 恢复，但不是云厂商网络拓扑或原生 ARM 硬件性能验证。没有执行的默认 180 秒完整等待、kill -9 后其他启动命令、包集合变更反例及原生主机安装路径，不能由这组结果推定通过。

APT 在上述四台虚拟机使用没有维护脚本、依赖或服务的本地测试包：仅批准已安装的 `witshield-smoke-fixture` 从 `1.0` 升为 `1.1`，完整包清单只出现该版本变化，`dpkg --audit` 干净。另持有真实 `/var/lib/dpkg/lock-frontend` POSIX 锁覆盖 CLI 全程，确认没有成功文案且包清单无变化。测试包被清除、临时 APT 配置恢复后，完整包清单与演练前一致。受控 `file:` 测试源使用 `trusted=yes`，没有验证真实发行商安全补丁或维护脚本的回滚能力。

锁冲突场景的 CLI 退出码在 Debian 为 `0`、Ubuntu 22.04/24.04 为 `1`，因为本版按修复前体检分数返回；测试直接核对逐项失败信息和完整包清单，没有将退出码当作修复成功证明。

## 尚未验证的发布路径

- 真实签名版本标签、公开 Release 资产、SHA-256、Sigstore 身份和 provenance，以及发布后的完整主机安装冒烟矩阵。
- 需要新增/删除包或改变未授权依赖的整机反例，以及真实发行商补丁维护脚本的副作用与恢复，继续保留 `NOT RUN`。
- 可选 DeepSeek 调用缺少获授权的 API Key，未实测；不影响不使用 AI 的本地体检。
- 用户暂缓 Gitee 仓库及令牌配置；Gitee 实际上传、附件可用性、国内首次下载及信任服务耗时均未实测。本地镜像夹具通过不等于国内链路通过。

正式发布仍受签名标签和 `release` Environment 人工审批约束。`check --fix` 首发为实验性；真实主机发现未解决的问题时应停止发布，不能用 CI、演示或实验性标识替代修复和复验。
