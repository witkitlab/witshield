# 终端演示素材

[`check.gif`](check.gif) 用于中英文 README；[`web/public/check-demo.gif`](../../web/public/check-demo.gif) 是逐字节相同的官网副本。

## 来源与边界

当前 GIF 是 **Pillow 对真实 stdout / PTY 的重播**，不是 VHS 实时录屏。数据来自一次获授权的隔离测试，源码提交 `c661430`，构建为 `v0.4.0-dev`。测试环境为 Ubuntu 24.04.5 amd64 容器，主机名统一为 `demo-vps`；使用真实 `sshd` 和全新 TCP SSH 连接，关闭连接复用。容器内没有 systemd，测试用 `systemctl` 适配器向真实 `sshd` 发送 SIGHUP。它不能代替完整虚拟机、云厂商网络或发行版矩阵演练。

演示中的真实变化为关闭 SSH 密码认证，以及把 `/etc/shadow` 权限从 `0644` 修为 `root:shadow 0640`。确认修改时，录制器先建立另一条密钥 SSH 连接，成功后才提交保留确认；修复后新密钥连接仍成功，密码登录探测失败。报告分数从 **27 变为 63**，问题从 **6 个变为 4 个**。两次均只完成 **7/8 项检查，覆盖率 87%**；容器缺少主机防火墙工具，也没有可读的 SSH 失败日志。剩余 root 登录策略和内核设置问题没有被修复，不能把结果理解为完整安全审计或“已经安全”。

[`capture.json`](capture.json) 保存去标识后的完整前后报告、实际 PTY 分块及其时间戳，以及上述确认探测的最小元数据。未读取或导出容器密码、公私钥、known_hosts、SSH 指纹或测试执行器。源记录本身使用 `demo-vps`；导出时还会移除 IP 字面量。文件中的 SHA-256 是构建程序和源记录的摘要，不是 SSH 密钥指纹。

SSH 与 shadow 确认场景实际持续 **0.277 秒**。为了阅读，GIF 按预览、二次登录确认、权限修复和重新体检分镜停留，总时长 **25.5 秒**。报告有节选，长行按画幅重新换行；完整原文在 capture 中。顶部“命令”栏用于说明调用方式，底部“录制动作”“录制验证”用于说明操作，均为画面注释，不是 CLI 输出或 shell 回显。原始 PTY 关闭了输入回显，因此没有向终端补写 `y` / `yes`。本次确认窗口为 60 秒，产品默认仍为 180 秒。

## 重建当前 GIF

需要 Python 3、Pillow，以及系统字体 `NotoSansCJK-Regular.ttc`。渲染器选用 TTC 内的 `Noto Sans Mono CJK SC`（索引 7）显示终端；所有帧共享固定调色板。

在仓库根目录运行：

```bash
python3 docs/demo/render.py --preview-dir /tmp/witshield-demo-preview
```

脚本同时生成 README 和官网 GIF，检查尺寸为 `1440×900`、时长小于 30 秒、文件小于 3 MiB，并验证两份副本完全一致；最后打印实际文件大小、帧数、时长和 SHA-256。预览 PNG 仅写入指定的临时目录。渲染只读取已去标识的 capture，不连接服务器或执行修复。

本次使用 Pillow `12.3.0` 生成并重新解码验收，结果为 **51 帧、25,500 毫秒、339,605 字节**，尺寸 **1440×900**；两份 GIF 的字节完全相同。SHA-256 为 `d51ecf51b7c7d653cb3f5a22f79c8cffe5b57151eeae407439fe3e97a96f9472`。已目视检查体检、预览、SSH 等待确认、shadow 预览、完成和复查六个关键画面，中文及证据行均在画幅内。

## 用 VHS 重新录制真实虚拟机

[`check.tape`](check.tape) 是供后续虚拟机复录的 VHS 脚本，**没有用于生成当前 GIF，也尚未由 VHS 执行验证**。先在可销毁的 Ubuntu/Debian 虚拟机准备相应问题、安装 CLI，缓存 sudo 认证，并保留独立备份和带外控制台。不得在生产机器运行，也不要为了演示降低现有服务器的权限。

脚本会批准 SSH 和 shadow 两项变更，只适用于恰好出现这两项可修复问题的演示机；若出现包升级、不同提示或步骤顺序，先调整脚本。修改 SSH 后的 8 秒停留期间，需要从另一个终端建立全新密钥连接；失败时立即中断，不能继续提交 `yes`。运行前再次核对输入时机，录制后逐帧审查。不同虚拟机的分数、问题和运行时间以实测为准，不能为了复现 27→63 修改报告。

```bash
WITSHIELD_DEMO_DISPOSABLE=yes vhs docs/demo/check.tape
```

真实虚拟机录制会覆盖 `docs/demo/check.gif`，需另行同步官网副本、控制体积与时长，并记录新证据。Ubuntu 22.04、Debian 12、ARM64、APT 升级/锁冲突、DeepSeek 和国内 Gitee 网络测试均不由当前素材证明；发布演练仍以[手工清单](../testing-check-cli.md)为准。
