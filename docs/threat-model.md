# 威胁模型

最后更新：2026-08-26。本文针对默认单管理员部署；它不能替代部署者自己的风险评估。

## 保护目标

按优先级保护：

1. 服务器控制权、服务可用性和管理员远程连接；
2. Agent/Controller 设备身份、管理员会话和 enrollment token；
3. AI API Key、Controller 主密钥、回滚材料；
4. 扫描证据、资产清单、Finding 与审计历史；
5. 更新链、发布制品和安全策略的完整性。

## 信任边界与攻击者

考虑以下攻击者：

- 能从网络访问 Controller 的匿名攻击者；
- 已取得普通服务器用户、容器或 Web 服务权限的本机攻击者；
- 恶意或被攻陷的 AI API 上游；
- 试图通过文件名、包元数据、日志或扫描证据实施提示注入的攻击者；
- 被攻陷的 Agent，尝试跨设备读取或影响其他设备；
- 获取旧 enrollment token、消息或发布包的重放者；
- 错误配置、误批准或失去 SSH 连接的合法管理员；
- 依赖、构建环境或镜像仓库供应链攻击者。

不假设 Controller、AI 模型或管理员永远正确。物理控制、内核/固件完全失陷和云厂商恶意不在妙盾能够可靠修复的范围内。

## 主要威胁与控制

| 威胁 | 典型路径 | 必要控制 |
|---|---|---|
| 未授权管理访问 | Controller 直接暴露公网、弱会话 | 默认 loopback、TLS 反代、单管理员认证、CSRF/Origin 检查、限速 |
| 设备冒充/重放 | 泄露注册令牌、重放旧任务 | 短期一次性 enrollment、设备独立身份、nonce/时间窗、幂等 ID |
| 跨设备越权 | 设备 ID 可猜、Controller 查询未校验归属 | 服务端从认证身份解析设备、拒绝客户端指定租户、对象级授权测试 |
| 提示注入变成 root RCE | 恶意日志/包名诱导模型输出命令 | 不信任扫描文本、结构化输出、动作 allowlist、审批、普通用户 Agent + 独立 Helper |
| Shell/参数注入 | 文件名/IP/服务名进入动作参数 | Helper 不接受 shell/路径，固定绝对程序、参数数组、规范化/白名单、测试边界字符 |
| SSRF | 自定义 API URL 或 Webhook 访问元数据服务 | 明示用户信任边界、DNS 后地址校验、阻止元数据/链路本地地址、禁止重定向和 AI 凭据的环境代理转发 |
| 凭据泄漏 | UI 回显、日志、进程参数、环境导出 | `0600` 文件、静态脱敏器、无 key 查询参数、错误响应截断、导出过滤 |
| 自动防御自锁 | 封禁管理员 IP、规则风暴 | loopback/私网保护、强制显式管理员 allowlist、TTL、速率上限、设备级紧急停止、执行前最终授权门 |
| 修复破坏业务 | 包升级、重启、防火墙改变 | 预检、预览、逐项批准、维护窗口、快照、验证、回滚和人工接管状态 |
| 审计抵赖/篡改 | 攻击者删除本地记录 | 当前记录事件 ID、动作与审批双方数据；哈希链、远端副本和时钟偏差专门记录属于后续加固 |
| 恶意更新 | Release 或镜像被替换 | SHA-256、Sigstore 签名、SBOM、固定 digest、更新不降级、可回滚 |
| 容器逃逸扩大影响 | `--privileged` 或 docker.sock | Docker 仅只读观察、不挂 socket、drop ALL、只读 rootfs、原生执行修复 |
| 资源耗尽 | 巨量日志、扫描并发、模型响应 | 输入/响应大小上限、超时、队列上限、并发限制、退避、磁盘配额 |

## AI 特有边界

所有来自服务器的字符串都可能是攻击者控制的，包括日志、进程参数、服务描述、容器标签、文件路径和包元数据。因此：

1. 发送给模型的内容是**数据**而不是可信指令；
2. 当前模型接口只能返回 `canExecute: false` 的解释，不能选择或提交动作；未来若引入结构化动作建议，也只能引用系统已注册的类型和参数；
3. schema 通过不代表安全，策略层还要验证权限、目标、影响和批准；
4. 模型拒绝、超时、幻觉或恶意响应必须 fail closed，不能自动降级为 shell；
5. 展示“模型建议”与“规则证据”的来源差异，避免用户把解释当成事实；
6. 当前只按固定字段白名单与类别过滤发送最小上下文，UI 明示这一边界但不提供逐字段预览；未来若扩大可发送数据范围，必须先加入逐字段预览和可配置选择，不能静默扩大上游可见面。

## 自动防御的危险案例

### SSH 临时封禁

必须防止：伪造来源日志、NAT 下误伤多人、IPv4/IPv6 规范化绕过、封禁 Controller/管理员、规则重复叠加、重启后永久残留。

建议安全条件：

- 多个时间窗口与足够事件数；
- 只处理已验证解析器产生的结构化来源 IP；
- loopback、链路本地、主机本地地址和显式 allowlist 永不自动封禁；部署者必须把实际管理出口地址/CIDR 加入 allowlist，首版不会可靠地自动推断 NAT、跳板机或动态管理员来源；
- 最短可用 TTL，自动解除；
- 按设备设置每小时封禁创建上限，待执行与已生效封禁都计入上限；同一来源不重复排队；
- 防火墙变更后立刻验证管理端口与 Controller 连接；
- 任一步失败则撤销本次动作并报警。

当前紧急停止是设备级的：它原子取消尚未开始的策略队列，并让 Agent 在进入 Helper 前的最终授权检查失败关闭；它不声称能取消已经进入 Helper 的操作。已经生效的封禁仍依赖 TTL 或显式回滚，因此带外访问仍是必要条件。

### 异常容器隔离

暂停容器可能中断数据库或控制面，且挂载卷仍可能被破坏。此动作在具备依赖关系识别、数据卷风险提示和恢复测试前，不应默认进入自动策略。

## 默认安全姿态

- Controller 绑定 loopback；
- 自动修复和自动防御关闭；
- 无 AI Key 也可使用规则扫描；
- 不使用遥测或公共控制中心；
- 官方 Docker 观察配置使用只读根文件系统、丢弃全部 capabilities，不使用 `privileged`，也不挂载 docker.sock；镜像不包含 Helper；
- enrollment token 不进入 URL或日志；网页一行命令会明确提示 shell 历史风险，并只使用 15 分钟、单次 token；
- 高风险动作需要新鲜批准，批准会过期且不可跨设备复用。

## 残余风险

- Helper 的实现漏洞或本机 token/组权限泄漏仍可能使普通 Agent 权限提升为 root；
- 设备 bearer 令牌泄漏不足以伪造特权动作结果（还需设备 Ed25519 私钥），但持久身份私钥与本机 Helper token 同时泄漏应视为整台设备失陷并立即撤销；
- root Helper 调用 apt、systemctl、sshd 与 nft 等固定系统程序，软件源或这些组件被攻陷时仍存在供应链/本机执行风险；
- 已取得 root 的攻击者可以绕过或篡改本机 Agent、日志和策略；
- 第三方 AI 上游会看到用户选择发送的数据，妙盾无法控制其保留策略；
- 回滚不是快照系统，包管理、数据库迁移、内核和网络改变可能无法完整自动恢复；
- 自动响应会改变线上状态，即使规则正确也可能影响 NAT、代理或集群环境。

部署者应保留独立备份和带外访问方式，并先在非生产环境演练修复与恢复。

## 发布前安全门槛

- 单元、竞态、集成与故障注入测试通过；
- 对注册、认证、API Key、动作审批、路径和网络输入做对抗性检查；
- 验证“重复消息/重复批准/重启恢复”不造成重复动作；
- 安装、升级、卸载不删除用户数据且校验发布制品；
- Docker 配置经 `docker compose config` 检查且没有高权限选项；
- SBOM、校验和、签名和 provenance 可被独立验证；
- 文档明确当版已实现和仍属路线图的能力。
