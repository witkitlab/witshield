# v0.4.0 · 独立命令行体检

本版本首次提供 Linux amd64 / arm64 的独立 `witshield` 程序，体检无需注册、安装常驻服务或开放管理端口。`witshield check` 展示安全分、检查覆盖率、优先处理的问题及修复建议，也支持 JSON 输出和最近 24 小时 SSH 登录失败统计。分数只代表已完成的检查，不代表服务器已经安全或没有被入侵。

**`witshield check --fix` 为首发实验性功能。** 在完成对应系统的真实主机演练前，只应在可销毁的测试机使用；操作前备份或创建快照，验证云厂商带外控制台可以登录，保留现有 SSH 会话。自动恢复不能替代整机备份或带外救援。

## 自动修复的范围

CLI 只调用现有的三类强类型修复流程，每项都先预检、预览并要求确认，不执行 AI 生成的命令。

| 问题 | 动作与边界 |
| --- | --- |
| SSH 密码认证开启 | 关闭 `PasswordAuthentication`；不涵盖键盘交互等其他认证机制，不能据此宣称“只允许密钥登录”。未找到可用公钥材料时拒绝修复；公钥文件存在仍不等于你的电脑一定能登录。 |
| `/etc/shadow` 权限过宽 | 仅处理该文件，恢复为 `root:shadow 0640`；没有 shadow 组时使用 `root:root 0600`。 |
| 已安装软件包待更新 | 一次最多升级 64 个明确授权的已安装软件包，拒绝新增、删除或未授权的依赖变化。软件包维护脚本及服务重启等副作用无法保证撤销。 |

SSH 修改后，必须从第二个窗口建立全新密钥连接，确认可用后再保留配置。默认确认窗口为 180 秒；超时、拒绝确认或等待期间按 Ctrl-C 时会尝试恢复。`kill -9` 或机器重启会中断计时，不能指望已退出进程继续恢复；下次以 root 启动任意 `witshield` 子命令时会先尝试处理恢复记录。恢复失败或无法重新登录时，使用带外控制台人工处理。

防火墙、内核参数、Docker 接口和 root 登录策略等项目只提供手动建议，不在本期自动修复范围内。

`--fix` 的退出码仍依据修复前的体检分数；退出码 `0` 不表示每项修复都成功。请核对逐项结果并重新体检。

## 下载与核验

[官网](https://witshield.witkitlab.com) 提供命令入口和终端演示。维护者完成正式发布后，可从 [v0.4.0 Release](https://github.com/witkitlab/witshield/releases/tag/v0.4.0) 获取以下资产。

- `witshield_0.4.0_linux_amd64`、`witshield_0.4.0_linux_arm64` 两个独立 CLI；完整归档也包含 CLI。
- `check.sh` 下载、校验并在临时目录运行 CLI；完整版安装仍使用 `install.sh`。
- `SHA256SUMS`、`SHA256SUMS.bundle`、SBOM 和 GitHub provenance。

`check.sh` 会核对程序的 SHA-256，并验证校验表的 Sigstore 身份为本仓库本次 tag 的 GitHub 发布工作流，任一校验失败都会停止。脚本自身仍需要信任下载来源，推荐先下载并审阅。手动下载请按[独立验证步骤](https://github.com/witkitlab/witshield/blob/v0.4.0/docs/releasing.md#独立验证)核对签名、哈希和 provenance；签名只能证明发布来源，不能证明程序没有缺陷。

## 验收记录与尚未完成的项目

真实主机演练的逐项结果、测试构建及限制以 [QEMU 矩阵最终 QA 记录](https://github.com/witkitlab/witshield/blob/v0.4.0/docs/qa/2026-10-31-cli-phase1.md)为准，并对照 [CLI 发布演练清单](https://github.com/witkitlab/witshield/blob/v0.4.0/docs/testing-check-cli.md)。演示、单个平台通过或分支 CI 通过均不代表全部系统已经验收；未完成的项目继续保留 `NOT RUN`。真实签名发布及公开资产的核验也需要单独记录，不能以本说明代替验证结果。

Release 公开后，[Release host smoke](https://github.com/witkitlab/witshield/actions/workflows/release-host-smoke.yml)会使用公开签名资产执行独立矩阵。其结果与发布前 QEMU 记录分开查看；公开后烟测失败应作为发布阻断事故处理，不能把 Release 页面已经出现理解为烟测通过。

Gitee 仓库和发布令牌尚未配置，本轮镜像默认关闭，国内下载、登录限制及验签耗时尚未实测。DeepSeek 为可选解读服务，本轮没有使用真实 API Key 调用；配置示例不代表供应商实测通过。不配置 AI 也能运行本地体检和交互式修复。
